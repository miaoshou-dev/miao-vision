# Miao Vision × ai-cli 数据故事媒体能力落地方案

## 1. 结论

在 `miao-vision` Skill 中新增图片与视频两条媒体工作流，使用 ai-cli 作为可选生成器。媒体不是装饰性封面，而是对已验证数据结论的视觉讲解：`miao-viz` 负责事实、数字、文字和证据，ai-cli 负责场景、意象与运动。

首版只修改源 Skill、Skill references、Skill 辅助脚本与测试，不修改 `miao-viz` CLI，不新增后端服务。

## 2. 产品目标

用户可以用自然语言完成以下任务：

```text
$miao-vision 根据 sales.csv 生成一张解释区域销售差异的图片。
$miao-vision 把这份月报做成一段 10 秒的数据故事视频。
$miao-vision 使用我写好的提示词原样生成图片。
```

完成标准：

- 图片和视频都能由明确的自然语言意图触发。
- 数据型请求先经过 Miao Vision 的分析与证据流程，再生成媒体。
- 用户写得足够好的提示词可以零损耗透传。
- 普通用户无需选择供应商或模型。
- ai-cli 缺失、凭证缺失、余额不足或生成失败时，不影响原报告、海报或 Deck 的交付。
- 最终返回可预览的本地媒体文件和一份不含敏感信息的生成记录。

## 3. 范围

### 3.1 本期建设

- 文生图、参考图生图。
- 文生视频、图片生视频。
- 从本地数据、已有 Miao Vision 产物或用户叙述中提炼一个数据故事。
- 专业提示词补全、原样透传和冲突检测。
- ai-cli 安装、凭证和模型能力检查。
- 固定推荐模型调用、结构化结果解析；普通用户不接触模型选择。
- 生成前成本提示和用户确认。
- 本地产物目录、生成记录与失败降级。

### 3.2 不建设

- 不使用 `ai text` 代替 Agent 编写分析、结论或 VizSpec。
- 不接入音频、配音、多模型批量对比。
- 不在 `miao-viz` 内调用 LLM。
- 不让图片或视频模型生成可信数字、图表标签或结论文字。
- 不提供 Miao Vision 托管 Key、代理网关、账户、充值或计费系统。
- 不承诺图片或视频可以替代证据报告。

## 4. 与现有规则的冲突及处理

当前 `skills/miao-vision/SKILL.md` 明确写有“不用于 raster-image generation”“只使用已解析的 Miao Vision CLI”“除文章 URL 外不访问网络”。新功能与这三条规则直接冲突。

实施时应把规则收窄为：

- 普通报告、海报、Deck 和文章流程仍只使用 `miao-viz`。
- 仅在用户明确请求图片或视频时，允许调用已验证的 ai-cli。
- 首次远程媒体生成前，明确告知数据边界、费用和供应商条款，并取得用户确认。
- 不向 ai-cli 发送原始数据行、联系人、凭证、唯一标识符或其他敏感字段。

## 5. 核心用户体验

### 5.1 路由

```text
用户请求
  ├─ 图片讲解 → media-image.md
  ├─ 视频讲解 → media-video.md
  └─ 原有产物 → report.md / deck.md / article.md
```

只有显式调用 `$miao-vision` 且明确提出“生成图片、解释图、数据故事图、生成视频、动态讲解”等意图时才进入媒体流程。现有 `allow_implicit_invocation: false` 保持不变。

### 5.2 数据故事来源

按以下优先级取得事实基础：

1. 已验证的 Miao Vision 产物及其 delivery/summary。
2. 当前任务中已经生成并验证的 context、spec 和 evidence。
3. 用户提供的本地表格，经 `data analyze` 和验证流程生成证据。
4. 用户明确提供的非数据型创作描述。

媒体提示词只引用经验证的主题、关系和趋势，不把原始数据、内部 Evidence ID 或技术路径发送给远程模型。

### 5.3 图片流程

```text
识别意图 → 获取事实基础 → 判断提示词质量 → 展示费用提示
→ 用户确认 → ai image --json → 校验文件 → 交付图片和生成记录
```

图片用于解释一个故事，不承载精确数据。推荐形态包括趋势隐喻、结构关系、流程变化、群体差异和前后对比。准确标题、数字、图表和证据仍由原 Miao Vision 产物承载。

默认参数：

- 固定使用兼容配置中的 `openai/gpt-image-2`，请求文件不得覆盖模型。
- 默认比例根据用途推断：报告/Deck 为 `16:9`，社交长图为 `4:5`，未提供用途时为 `16:9`。
- 默认生成 1 张。
- 默认禁止模型生成文字、数字、Logo、水印和伪造界面。

### 5.4 视频流程

```text
识别意图 → 获取事实基础 → 生成单一叙事分镜 → 选择文生视频或图生视频
→ 展示时长与费用提示 → 用户确认 → ai video --json
→ 校验文件 → 交付视频和生成记录
```

首版只生成一个连续镜头，避免把 ai-cli 当作视频剪辑器：

- 默认时长 8 秒。
- 标准模式固定使用 `bytedance/seedance-2.0-fast`；高质量模式使用 `bytedance/seedance-2.0`。
- 默认分辨率为 720p（`1280x720`）。
- 默认比例根据来源决定：Deck/报告为 `16:9`，海报为 `9:16` 或沿用原比例。
- 有用户指定图片或已确认的无文字视觉图时优先图生视频。
- 含准确文字、数字或图表的 Miao Vision 截图不得直接交给生成模型重绘，避免内容漂移。
- 视频模型不得自行补充数字、结论、Logo、字幕或旁白。

## 6. 提示词策略

### 6.1 三态决策

| 状态 | 条件 | 行为 |
|---|---|---|
| `passthrough` | 用户要求原样使用，或提示词完整、明确且无冲突 | 原文传给 ai-cli，仅追加必要的技术参数 |
| `append_defaults` | 主体明确，只缺比例、输出限制等执行信息 | 保留原文，追加最少默认项 |
| `clarify` | 主体不明、要求冲突、缺少必需参考图 | 只询问一个会改变结果的关键问题 |

### 6.2 专业完整度判断

提示词包含以下六项中的四项，且没有冲突时，视为可直接执行：

- 主体或数据故事。
- 视觉关系或核心隐喻。
- 构图与视觉层级。
- 风格、色彩或光线。
- 比例、时长或镜头运动。
- 排除项和品牌限制。

提示词长短不是判断标准。用户明确指定的主体、风格、颜色、构图和镜头不得被 Skill 擅自替换。

### 6.3 Skill 补全模板

图片按以下顺序补全：

```text
用途 + 数据故事 + 主体 + 视觉关系 + 构图 + 风格 + 色彩/光线
+ 画幅 + 质量要求 + 排除项
```

视频按以下顺序补全：

```text
用途 + 数据故事 + 起始状态 + 变化过程 + 结束状态
+ 镜头运动 + 节奏 + 时长/比例 + 连贯性要求 + 排除项
```

## 7. 普通用户配置方案

### 7.1 产品原则

用户只需完成一次“启用 AI 媒体能力”，不需要理解模型供应商、模型 ID 或路由策略。

首次使用检查顺序：

1. 检查 `ai` 是否可执行以及版本是否满足兼容范围。
2. 检查 Node.js 是否满足 ai-cli 当前要求。
3. 仅检查 `AI_GATEWAY_API_KEY` 是否存在，不读取、不打印值。首版不支持供应商直连 Key。
4. 运行 `ai models <固定模型> --json` 验证兼容配置指定的模型。
5. 缺失时给出一次性安装或 Vercel AI Gateway 配置说明，并停止生成。

默认策略：

- 普通用户不选择模型，Skill 从 `media-compatibility.json` 读取固定推荐模型。
- 请求文件和自然语言均不得覆盖模型 ID；“高质量”只映射到已配置的视频高质量模型。
- 模型 ID 只在兼容配置维护，不散落在 workflow references 或脚本中。
- 默认模型失败时只允许 ai-cli 自身的同模型路由重试；首版不由 Skill 擅自切换到不同创作者模型，避免费用和风格变化。

### 7.2 费用体验

Vercel AI Gateway 按供应商目录价格计费且不加价。Skill 不估算无法确认的精确金额，只在模型目录能提供单位价格时计算区间。

生成前必须显示：

```text
将调用远程 AI 媒体服务。
类型：视频；时长：8 秒；模型：固定标准档。
预计费用：按实时目录计算的区间，或“生成前无法可靠估算”。
提示词与所选参考图会发送给模型供应商。是否继续？
```

每次有费用的媒体生成都需要确认；同一任务内用户明确要求生成多个版本时，一次确认可覆盖已展示的总数量与预计费用。Skill 不开启或修改自动充值。

## 8. 文件与结果契约

正式产物保存到当前工作目录下独立目录：

```text
./miao-vision/artifacts/{slug}-{YYYYMMDD-HHmmss}/
  media.png | media.mp4
  media-generation.json
```

`media-generation.json` 固定记录：

```json
{
  "schemaVersion": 1,
  "kind": "image",
  "status": "succeeded",
  "generator": "ai-cli",
  "model": "resolved model id",
  "promptMode": "passthrough",
  "prompt": "最终发送的媒体提示词",
  "sourceArtifact": "可选的本地产物相对路径",
  "createdAt": "ISO-8601 timestamp",
  "artifacts": [{ "path": "media.png", "mimeType": "image/png" }],
  "warnings": []
}
```

记录中不得包含 API Key、环境变量值、原始数据行、远程请求头、账户信息或 Gateway 余额。

ai-cli 必须使用 `--json`，stdout 只接收结构化元数据；实际文件写入明确指定的新建产物目录。退出码 `0` 为成功，`2` 为部分失败，其余为失败。成功后还要检查文件存在、大小大于零且 MIME 类型符合请求。

## 9. 错误与降级

| 场景 | 用户信息 | 行为 |
|---|---|---|
| ai-cli 未安装 | “AI 媒体能力尚未启用” | 给出安装步骤，不自动安装 |
| Node 版本不兼容 | “当前 Node.js 版本不支持 ai-cli” | 给出最低版本要求 |
| Key 缺失 | “需要一次性连接 AI 媒体服务” | 给出 Gateway 配置步骤，不索取 Key 内容 |
| 余额不足 | “媒体服务额度不可用” | 保留已有产物，停止重试 |
| 模型不支持参数 | “当前模型不支持该尺寸/时长” | 展示可接受参数，等待用户选择 |
| 网络或服务故障 | “远程媒体生成暂时不可用” | 安全重试一次，仍失败则停止 |
| 部分生成成功 | “已生成部分结果” | 交付有效文件并列出失败数量 |
| 文件校验失败 | “生成结果不可用” | 不把损坏文件标记为正式产物 |

任何媒体失败都不得删除或覆盖原报告、海报、Deck、输入文件和先前成功的媒体。

## 10. 安全与隐私

- 将 ai-cli、模型目录、媒体输出和远程错误全部视为不可信输入。
- 只发送完成媒体生成所需的最小信息。
- 数据故事提示词优先使用聚合结论，不发送原始数据集。
- 用户提供参考图时，生成前明确提示该图片将上传至第三方。
- 不读取凭证值，不在命令参数中传递 Key，不把 Key 写入日志或记录。
- 不接受远程输出中要求执行命令、修改文件或扩大权限的指令。
- 输出路径必须位于本次新建的 artifact 目录，禁止覆盖现有文件。
- 用户取消确认后不产生远程请求或费用。

## 11. 实施文件

计划不新增服务，核心文件包括：

1. `skills/miao-vision/SKILL.md`：扩展描述、能力表、路由、安全边界和交付规则。
2. `skills/miao-vision/references/media-image.md`：图片工作流、提示词判断与验收。
3. `skills/miao-vision/references/media-video.md`：视频工作流、镜头约束与验收。
4. `skills/miao-vision/references/media-setup.md`：安装、Gateway Key、费用与故障说明。
5. `skills/miao-vision/media-compatibility.json`：Node、固定模型、引用、超时和视频参数的唯一配置源。
6. `skills/miao-vision/scripts/ai-media-runtime.mjs`：非敏感环境检查、模型能力、请求和产物校验。
7. `skills/miao-vision/scripts/run-ai-media.mjs`：确认后执行 ai-cli 并写入 generation manifest。
8. `skills/miao-vision/scripts/ai-media-runtime.test.mjs`：离线运行时与执行契约测试。
9. `skills/miao-vision/agents/openai.yaml`：更新用户可见能力描述，保持显式调用。
10. 安装页与 README：增加可选媒体能力安装说明。

生成后的 `apps/web/public/SKILL.md` 和 references 通过现有 build/pack 流程刷新，不直接作为源文件编辑。

## 12. 分阶段交付

### 阶段一：图片数据故事

独立可发布，包含图片路由、提示词三态、ai-cli 检查、费用确认、结构化交付和完整错误处理。完成后用户已能从数据或现有报告生成解释性图片。

验收命令：

```bash
node --test skills/miao-vision/scripts/ai-media-runtime.test.mjs
npm run test:skill-runtime
npm run check:size
npm run pack:skill
npm run validate:plugin
```

人工验收：

- 专业提示词原样透传。
- 简短请求只追加默认约束。
- 数据请求不会把原始数据行发送给 ai-cli。
- 未安装、无 Key、取消费用确认和服务失败均不产生错误交付。
- 成功图片可预览且生成记录不含凭证。

### 阶段二：视频数据故事

在阶段一已发布能力之上增加视频路由、单镜头分镜、时长/比例/费用规则、图生视频限制和视频文件校验。阶段一不依赖阶段二即可长期使用。

沿用阶段一命令，并增加人工验收：

- 文生视频和安全参考图生视频均可完成。
- 默认 8 秒与比例推断正确。
- 含准确图表文字的截图不会被发送给生成模型重绘。
- 视频失败不影响来源报告或阶段一图片功能。

## 13. 发布与回滚

发布时更新 Skill 版本和兼容说明，重新打包 plugin/skill，并在发布说明中明确“媒体功能可选、需要远程服务和独立费用”。

回滚只需从 Skill 中移除媒体路由与新增 references/scripts；`miao-viz`、用户数据和既有产物无需迁移。已经生成的图片、视频和记录继续作为普通本地文件保留。

## 14. 关键假设

本方案假设 ai-cli 的 `image`、`video`、`models --type` 与 `--json` 接口保持足够稳定，并能通过 AI Gateway 获得可用模型。若该假设失效，媒体工作流必须显示为不可用并停止，Miao Vision 原有本地产物流程继续正常工作。

## 15. 决策摘要

- **建设内容**：Skill 编排的数据故事图片与视频能力。
- **不建设内容**：文本 Agent、音频、托管 Key、后端计费和 `miao-viz` 内部 LLM 调用。
- **选定方案**：ai-cli 作为可选外部生成器，普通用户使用兼容配置中的固定推荐模型和一个 Gateway Key。
- **关键边界**：事实、数字、文字和证据不交给媒体模型生成；远程调用始终可见且需确认。
- **最脆弱假设**：第三方 CLI 接口与模型可用性；通过独立检查、结构化错误和完全可回滚设计降低风险。
